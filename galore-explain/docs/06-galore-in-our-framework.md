# 06 · GaLore 在本项目中的装配

## 这一篇讲什么

上一篇把 GaLore 的数学推完了。这一篇回答一个更窄、更硬的问题：**在 Qwen3.6-35B-A3B、
单张 RTX 3080 20 GB、60 GB 内存、专家 int8 存 host 并逐层流式这一套约束下，GaLore 具体怎么装？**
每个数字都给实测值和来源，并按五档标注口径：**实测**、**投影**（每层实测 × 40，未跑过完整 40 层）、
**未落盘**（只有运行时打印，没有 JSON）、**待重测**、**UNVERIFIED**；被作废的直接写 **已作废**。
路径相对于 `/data/train35b/`，**任何数字冲突时以 `STATE.md` 为准**。

记号沿用 [`00-notation.md`](00-notation.md)：`W` 是 `m×n` 权重，`G` 是梯度，`P` 是 `m×r`
列正交基，`R` 是 `r×n` 累加器，`Ŵ` 是 int8 骨架，`s` 是每输出通道尺度，`K` 是折叠间隔，
`T` 是基刷新间隔。

## 读完你会知道

- 为什么全秩 Adam / 8-bit Adam / Muon 在这里全部被算术排除；
- 秩 8/16/32/64/128 各自的状态字节数，哪一个真的装进 20.8 GB；
- 三个区的内存表、精确张量形状，以及各处口径为什么对不上；
- 一次更新从 `G` 到 `Ŵ` 的路径，以及仓库里哪些环节已实现、哪些只是设计；
- 折叠下界（量化）与上界（基腐坏）为什么打架，EF 如何拆掉下界但拆不掉上界；
- 为什么 rank 的验收要用 held-out CE 而不是谱阈值，以及一条"看起来保守"的规则如何变成无解；
- 为什么真正的成本在刷新的 SVD，而不在折叠；
- 为什么"必须 EF"而"SR 还是 RTN"不是关键；
- 六个必须写进 limitations 的事实，以及一个可以手算的例子。

## 1. 为什么 GaLore 不是可选项

### 1.1 全秩优化器的算术

专家参数 **32.21 B**（`DESIGN.md` §2；survey §1 第 31 行：`40 × 256 × (1024×2048 + 2048×512)`）。

| 方案 | 字节/参数 | 专家状态 | + bf16 权重 64.4 GB | 结论 |
|---|---|---|---|---|
| Adam，fp32 `m,v` | 8 | **257.7 GB** | 322.1 GB | 差 5.4 倍 |
| Adam，bf16 `m,v` | 4 | 128.8 GB | 193.2 GB | 不 |
| 8-bit Adam | 2 | **64.4 GB** | 128.8 GB | 不 |
| Muon（bf16 动量） | 2 | 64.4 GB | 128.8 GB | 不 |
| Adam-mini | ≈2 | 64.4 GB | 128.8 GB | 不 |

`2·4·32.21e9 = 257.68 GB` 只算矩，加权重是 **322.1 GB**，机器只有 60 GB。预算是
`60 − 5（OS）− 34.2（int8 专家）= 20.8 GB`（survey §1 第 36–37 行）。8-bit Adam 仍大 3.1 倍。
**这不是调参问题。**

### 1.2 状态公式与 rank 表

论文式（只有 `P, M, V`；`M,V` fp32、`P` 按 1 B/元素）：

```text
bytes per matrix = 2·r·n·4 + m·r                 (1)
```

对 **20,480** 个真实矩阵按代码朝向求和（10,240 个 `[1024,2048]` + 10,240 个 `[2048,512]`；
`ΣP = 31.457 M`、`ΣR = 26.214 M`，`STATE.md` §6）：

```text
本文口径 = P int8 + R bf16 + m,v 8-bit
         = r·ΣP·1 B + r·ΣR·2 B + r·ΣR·2 B
         = r × (31.457 + 52.428 + 52.428) M·B
         = r × 136.313 M·B                        (2)
```

| rank | 式 (1)：论文口径（fp32 矩，无 `R`） | 本文口径 (2)：`P` int8 + `R` bf16 + `m,v` 8-bit | 装 20.8？ | 当前 `train/` 代码（`P,R,m,v` 全 fp32） |
|---|---|---|---|---|
| 8 | 1.93 GB | **1.09 GB** | 是 | 3.52 GB |
| 16 | 3.86 GB | **2.18 GB** | 是 | 7.05 GB |
| 32 | 7.72 GB | **4.36 GB** | 是 | 14.09 GB |
| 64 | 15.44 GB | **8.72 GB** | 是 | 28.19 GB |
| 128 | 30.87 GB | **17.45 GB** | 否 | 56.37 GB |

三列是**同一批矩阵、三种 dtype 口径**，不是三个互相矛盾的测量。第三列是 `train/` 现在的实现
（`P/R/m,v` 全 fp32，`STATE.md` §6 记 r=16 为 7.05 GB）——上 40 层前必须换成第二列的 dtype。

**早期口径错在哪（一句话）。** 旧文档的 2.68 / 5.37 / 10.74 / 21.47 GB 用的是 `r × Σn × 4 B`、
`Σn = 41.94 M`：它把 `down_proj` 当成 `[512,2048]`（转置了朝向），并且混用了"int8 基 + 16-bit 矩"
两种假设。按代码朝向 + 单一 dtype 口径，正确值是 **1.09 / 2.18 / 4.36 / 8.72 / 17.45**。
r=16 上差 0.5 GB，不影响可行性判断，但报账必须统一到式 (2)。

### 1.3 rank 怎么定：验收看 loss，元数据看谱

**内存只排除上界**：r=64 占 8.72 GB（20.8 的 42%），r=128 要 17.45 GB，放不下。GaLore 原文按
"min-dim 的 25%"取 rank（`r=1024/4096`），照搬到 `m=1024` 给出 r=256，也不可能。所以 rank 必须实测。

**验收判据是 held-out CE 平价**，不是谱阈值。50 步、16384 token/step、cap 2.0、aux 0.01、lr 1e-4、
同一数据顺序，只改 `--rank`（`runs/M1/rankfixed/`）：

| r | held-out CE@50 | 相对 r=16 | tok/s | 峰值 GB |
|---|---|---|---|---|
| **16** | **4.2568** | — | 1,252 | 17.43 |
| 32 | 4.2525 | −0.0042（z −1.20，11/16） | 1,250 | 17.43 |
| 64 | 4.2625 | +0.0057（z +0.60，10/16） | 1,247 | 17.44 |

最大差 **0.010 nats**，低于本项目 **0.014 nats** 的重复噪声地板，没有 |z| > 1.4。**在这个时程上
rank 不影响 loss**，所以取 **r=16**（2.18 GB），把 r=32/64 留作敏感度。

**谱上的代价是真的，不能藏**：逐专家、能量加权、25 个连续 step，r=16 的 p10 捕获率是
**0.927–0.971**、中位 **0.985–1.000**，最差的 L1/L2 有 **16–60%** 的单步低于 0.99；r=32 的 p10 是
0.964–0.988，r=64 是 0.985–0.996（`research/m1/REPORT.md` §12.1）。

**这里有一个值得记住的教学点：看起来"保守"的谱规则可能是无解的。** 如果按字面执行
「每层每矩阵 p10 ≥ 0.99」，r=16 失败（0.927）、r=32 失败（0.964）、r=64 失败（0.985），
**只有 r=128 过（0.996），而 r=128 的 GaLore 状态要 17.45 GB，装不下**（`REPORT` §12.1 写的
「≈21 GB」用的是旧的 2.68 GB 基准）。也就是说那条规则在可行 rank 上永远不成立——
它是在「死专家 `PR ≈ 1`」的画面上校准出来的，而那个画面本身是 bug（§0 的框）。
**验收应该用你真正在意的量（loss），并配一个噪声地板**；谱只用来解释代价与做敏感度分析。

**未验证**：50 步只覆盖 2 次折叠、5 次刷新，更长期的低秩误差累积没有被排除（UNVERIFIED）。

rank 翻倍只改变 `2mnr` 这一项 FLOPs（§5），在 7.30 s 的步时里占比很小；更精确的速度差没有可信
读数——`runs/A` 的 tok/s 来自 capacity 有缺陷的版本（见 §0 的框）。

## 2. 三区设计

按"谁必须在显存、谁的流量能被计算盖住"分区（`DESIGN.md` §6.1）：

| 区 | 参数 | 存法 | 位置 | 计算 |
|---|---|---|---|---|
| **常驻**：注意力 + shared + router | 1.43 B | bf16 + GaLore `r=256` | 显存 | bf16 张量核 105 TFLOP/s |
| **流式**：专家 | 32.21 B | int8 + GaLore `r=16`（保守回退 `r=64`） | pinned host → 显存 | dequant 或 int8 GEMM |
| **冻结**：embed / vision / MTP | 1.29 B | bf16 | host | 不训练 |

注意力必须常驻，因为它占每 token FLOPs 的 **51%**（`DESIGN.md` §2：hidden 2048，单层注意力
33.76 M 参数 > 单层激活专家 28.80 M），是无 PCIe 的计算，正好填专家流式的空隙。

### 2.1 显存 20 GB

| 项 | GB | 来源 |
|---|---|---|

| 其 GaLore 状态 `r=256` | 1.43 | 同上（分配值，非实测） |
| 层输入激活（16,384×2048×2×40） | 2.68 | 同上 |

### 2.3 实测每层成本

| 项 | 实测 | 来源 |

最后一行的绝对值（1.54 s / 1.183 s）来自 capacity 有缺陷的版本，**不要引用**（`STATE.md` §5）。

### 2.4 从每层到整步：投影与实际差 18 倍

`STATE.md` §5 的账本是**投影**：每层实测 × 40，16384 token/step，`step = max(compute, PCIe) × 1.06`。
（这里的 A / B 是账本的两行配置，不是 §2.3 的"方法 A / 方法 B"。）

| 配置 | 步时 | tok/s | 口径 |
|---|---|---|---|
| A：bf16 专家，cap 2.0 | 8.43 s | 1,944 | 投影 |
| **B：int8 专家，cap 2.0（推荐）** | **7.30 s** | **2,246** | 投影，**不含刷新** |
| B + GDN 优化，cap 2.0 | 6.92 s | 2,366 | 投影，不含刷新 |
| B + 刷新 | **待重算**（旧的 8.47 / 9.64 / 11.99 / 19.02 s 建立在"117 s/次"上，已作废） | — | §4.7 |
| 四层实现：普通步 / 300 步平均 | **11.92 s** / 13.08 s | ≈1,370 / 1,252 | 实测（`STATE.md` §3、§5） |

**引用 2,246 tok/s 必须同时说"不含刷新"**：账本里没有 GaLore 的刷新/折叠项，而它是一阶的（§4.7）。

差 **约 18 倍**：投影每层 168 ms（`(7.30 − 0.594) / 40`），四层合计 0.67 s；实测普通步 11.92 s，
分到每层 2.83 s（`(11.92 − 0.594 − 0.015) / 4`）。差在**这份实现**，不在内核：

- 层级 checkpoint 让每层前向跑两遍，`_mm_T` 被调 96 次/步，**3.48 s/步 = 29%** 全是它；
- 每次调用搬 gu 约 **17.2 GB**（不是"1.6 GB 权重"）：dequant 含 5.91 GB fp32 中间体、跨步
  `transpose().contiguous()` 只有 241 GB/s、`cat` 再走一趟；
- 专家 gather 的反向 `scatter-add` 单核 **2.24 s = 18.9%**（bf16 atomicAdd 只有 5.5 GB/s，
  且 90.6% 的行是 padding）。

已落地的两个修复（fixA 融合反量化核 + fixB 分段 fp32 散播）把 11.92 → **7.76 s / 2,111 tok/s**
（实测 5 步，`sha e1adc0e2…`）。注意阶梯表里 7.20 s / 2,276 tok/s 那一行**含 fix3**，而 fix3 因为
要 +1.65 GB 显存**没落**——这两个数不能混用。归因见 `research/m4/PROFILE.md` §8（99.1% 的时间有归属）。

**所以 2,246 tok/s 是"这些内核接好、刷新关掉之后能到多少"，不是"现在能跑多快"。** 把这张表当
现状会错 18 倍。

## 4. 更新路径：逐步对照

**七步在 `train/block_train.py` 里都实现了**（762 行，2026-11-19 版）：折叠是 `ExpertStore.fold()`
（`:301`），刷新是 `Block.refresh_basis()`（`:422`，默认 `--basis svd`，且**先折叠再换基**，
`order="bad"` 保留作反例）。下面按"这一步在算什么"讲，行号只给函数入口，不再给易腐的区间。

### 4.1 有效权重

```text
W_eff = deq(Ŵ) + P R                                    (2)
```

`ExpertStore._eff`（`block_train.py:274`）按 64 个专家分块：`q.float()*s[...,None]`
转 bf16，加 `bmm(P,R)`，再 `cat`。分块是为了把 fp32 临时量从 2.15 GB 压到 0.54 GB。
**已实现，但每步调用 16 次**（每个 2048-token 序列一次），只有 2 次必要——这占前向的 50%、
整步的 24%（`runs/A/REPORT.md` §3）；`--cache-dequant` 提到循环外后步时 1.528 → 1.319 s，白拿 1.15×。

### 4.2 前向

方法 A：`bmm(X, W_effᵀ)`（`fwd` 的 method-a 分支，:283）。方法 B：int8 GEMM + 两个小 bf16 GEMM（同函数）：

```text
y = int8_gemm(q(X), Ŵ) + (X Rᵀ) Pᵀ                       (3)
```

修正在**输出空间**做，避免物化 `P R`：成本 `2M·r·(m+n)` 而不是 `2M·m·n`。`M=128, r=64` 时
`gate_up` 的修正是 50.3 MFLOP，物化要 268 MFLOP，省 5.3 倍。

### 4.3 拿到 G

`G = ∂L/∂W`，`m×n`，bf16，用完即弃。方法 A 由 autograd 对 `W_eff` 求导产生；方法 B 里
`dW = dYᵀX` 不需要权重，backward 只流一趟权重（`DESIGN.md` §6.2）。
**前向路径里 `G` 不落地**：`R` 是叶子、`P` 是常量，autograd 直接给 `∂L/∂R = PᵀG`，`G` 被丢掉。
SVD 刷新要的是 `G`，所以另开一条旁路：`--dw` 打开的 dW 捕获（`_DWCapture` → `_CAP["acc"]`）
在 backward 里按专家累 `dYᵀX`，`refresh_basis` 直接对这份 `acc` 求 SVD。**代价是每个刷新周期
多留一份 `m×n` 量级的梯度缓冲**，这是 §5 内存表之外的临时开销。

### 4.4 投影与 Adam

```text
G̃ = Pᵀ G ,  M ← β₁M + (1−β₁)G̃ ,  V ← β₂V + (1−β₂)G̃²
D = M̂/(√V̂ + ε) ,  R ← R − ηD                            (4)
```

`self.optR = Adam([R_gu, R_d], lr=0.0)`（`Block.__init__`，`:397`），`set_lr` 在 `:405`。
`G̃`、`D` 都是 autograd/优化器内部量，代码里看不到。

### 4.5 累加

式 (4) 的 `R ← R − ηD` 就是累加。**折叠打开时**（`--fold K>0`）`R` 每 `K` 步被清一次，是有界的；
**`--fold 0` 时无界累加**，`W_eff` 越来越偏离 int8 骨架，最终等价于"int8 初始化 + 秩 r 的 LoRA"，
**不再是 int8 主权重 + 修正**。短跑看不出来，所以"无界累加"只剩在关掉折叠的消融里。

### 4.6 折叠（每 K 步）

```text
W_tmp = deq(Ŵ) + P R ;   Ŵ ← Q(W_tmp) ;   R ← 0
```

`kernels/galore_fold.py`，实测（r=32，单层 `NE=256, N=1024, K=2048` 的 store）。**注意 scope**：
这几个数测的是 **`gate_up` 半区（0.503 GB）**，不是整层：

| 项 | 值 |
|---|---|
| 融合 fold 内核，`gate_up` 半区 | **4.1 ms**（0.503 GB） |
| 整层（`gate_up` + `down`，1.543 GB） | **≈6.6 ms** |
| 纯 int8 拷贝（同一 0.503 GB 区域的地板） | 1.57 ms |
| fold / copy | **2.61×** |
| int8 码完全一致率 | **100.000%**（对 `fold_torch`） |
| 全模型 D2H 地板 | **1.357 s**（34.2 GB / 25.2 GB/s，单次折叠的写回） |

**这三项（4.1 ms / 2.61× / 100%）只有运行时打印，没有落盘 JSON**（`STATE.md` §8）。早期文档把 4.1 ms
写成"每层"，又把 6.6 ms 记成"卡上有别的进程时的复测"——实际是**两个 scope**：半区与整层。

**折叠不是被付的那一项。** 折叠内核是毫秒级（上面那两行），而**一次刷新步是 11.72 s**（§4.7）——
两者差三个数量级。所以"折叠摊到每步 54 ms，约等于免费"这个说法只对折叠自己成立，
它回答的不是"GaLore 每次维护要花多少"。

**scale 冻结**（`galore_fold.py:5-8`）：折叠间隔内 absmax 几乎不动，冻结 `s` 把"absmax 扫描 +
存储"两趟并成一趟。代价是长期单调增长的通道可能 clamp 到 ±127，但**没有测量**（UNVERIFIED）。
**读是免费的**：折叠时该层权重已在 GPU 上（前向/dX 刚用过），34.2 GB 的读是 HBM（54 ms），
不是 PCIe；唯一新增的是写回。这是整个设计最容易被忽略的一点。

### 4.7 刷新（每 T 步）

```text
（此时 R = 0）  P ← U_{:,1:r}(G)
```

**先纠正一个最容易读错的量级：一次刷新步只重拟合一层。** 两个驱动都把刷新**逐层轮换**——
`m1_run.py` 的 `due[i]`（`:279-308`）和 `model4.py` 的 `tgt = (step // refresh) % n_lay` +
`capture_now = ... and (i_ == tgt)`，并且 `refresh_layers` 会跳过 `_dw` 为空的层。所以实测的
**11.72 s 是"一层"的代价**，不是四层的（普通步 12.08 s → 刷新步 23.8 s，`STATE.md` §5）。
早期文档把它当成四层之和，于是凑出了"40 层 117 s/次"——**那个数作废**。

**这 11.72 s 里也不全是基。** 一次刷新步要做 `fold()` → `topr_basis(gu)` → `topr_basis(d)` →
`qr_orthonormalize` → `measure()` → PR 诊断（对 top-8 活专家做 `svdvals`）。其中 `measure()` 每个
32 专家 chunk 都构造 `P Pᵀ`（`[c,N,N]`）再 `bmm(pj, x)`（`[c,N,K]`）：gu 约 **1.65 TFLOP/层·矩阵**，
与基计算本身（gram bmm 1.1 + eigh 0.37 TFLOP）**同量级**，而它只输出一个捕获率数字，**生产不需要**；
PR 诊断同理。**组件拆分正在测**（`runs/M1/refresh/`）。在它出来之前：**只引用"每层 11.72 s"，
不发布任何 40 层刷新数字**。

**为什么慢：不是批处理不够。** `topr_basis` 已经按 16 个专家一批做 `eigh`/`svd`，不是 256 次逐专家
启动；慢在 `eigh`/`gesvdj` **算术强度低、且完全不碰张量核**。所以 FLOP 比只是收益的上界，杠杆是
**换成只做 bmm 的算法**（随机 range-finder：CPU 已验证 p=10、q=2 时对精确 SVD 的捕获损失 ≤1e-5、
子空间夹角 0.03–1.8°；`gu` 每矩阵 13.96 → 0.66 GFLOP，21×；`train/topr_rf.py`，未接线）。

**量级结论不变，数字变坏了。** 按"每层每 T 步刷一遍"放大到 40 层是 `40 × 11.72 / T` = `468.8/T`
（四层驱动里刷新是逐层轮换的，所以单层的实际间隔被拉长到 `n_lay·T`；折算是按 40 层口径）。
T=100 也有 **4.7 s/步**——比上一版文档写的 1.17 s/步 大 **4 倍**，而且**这仍是含诊断的上界**。
所以"刷新是一阶成本、rank 不是约束"这个结论**不但没变，反而更强**；待拆分出来的是倍率，不是方向。

**为什么必须这么密：基每步都在转。** 用 step t−1 拟合的 rank-32 基去捕获 step t 的能量，GDN 三层
只有 **0.20–0.40**（oracle r=32 是 0.995），而 L3（full attention）稳在 **0.81–0.97**。一步陈旧就
丢掉 60–80% 的能量——**GDN 的约束是刷新间隔，不是 rank**（`research/m1/REPORT.md` §12.3）。

**折叠节奏不是独立的。** 每个 20 的倍数都是 10 的倍数，刷新分支总是先跑，所以 **fold-only 的步数
恒为 0**：`K=20` 是死代码，实际折叠节奏**就是**刷新节奏（`STATE.md` §5）。名义 `K=20`、`T=10`
的真实含义是"每 10 步有一个刷新步（轮换到下一层），顺带折一次"。

**曾经的缺陷，现已修复。** 旧版 `ExpertStore.__init__` 用 `randn/sqrt(m)` 初始化 `P` 且永不更新，
而且没有做 QR——实测 `‖PᵀP−I‖_F` 在 r=16/32/64 时是 0.60/1.09/2.11，那根本不是投影。
旧 harness 跑的因此是**随机投影**（Flora 一类），**不是 GaLore**。修复后（`--basis svd` 为默认）
`P` 来自按专家捕获的 `dW = dYᵀX` 的 SVD 并做 QR：`‖PᵀP−I‖_F` 降到 3.6e-6~8.9e-6，
捕获率按 §1.3 的新口径（中位 0.985–1.000、p10 0.93–0.97），`--basis random --fold 0 --refresh 0`
仍可逐位复现旧路径。
随机基不用梯度谱，`χ` 的期望是 96.9%（推论 8.2）——这是修复前的对照组，保留作分析。

## 5. 为什么 GaLore 与 int8 互相需要

### 5.1 量级：|ΔW|/q ≈ 0.83

每输出通道对称量化，`s = absmax/127`，台阶 `q = s`。用 `bench/foldnoise.py` 在真实权重上测到的
`σ_W = 6.14e-3`（〔`bench/foldnoise.json`: `sigma_W` = 0.0061355〕）与 `absmax ≈ 2.5σ_W`（脚本自己的模型）：

```text
q ≈ 2·2.5·6.14e-3/255 = 1.204e-4                          (5)
|ΔW|/q ≈ 1e-4 / 1.204e-4 = 0.83                          (6)
```

**一个典型更新比一个台阶还小**（survey §1 第 43–49 行）。每步折叠时 RTN 会把 83% 的步长舍成
0 或 1 格，单步相对误差 `sqrt(x(1−x))/x = 45%`（`x = 0.83`）。

### 5.2 下界：累积多久够一格

随机游走模型 `|ΣΔW| ≈ η√K`，换成台阶：

```text
|Σ ΔW|/q = 0.83·√K ,    K ≥ (α/0.83)² = 1.45·α²           (7)
```

| α（要求 ≥ 几格） | `K_min` |
|---|---|
| 2 | 5.8 |
| 4 | 23.2 |
| 6 | 52.2 |

`K=25` 对应 `0.83·5 = 4.15` 格，落在 α=4 与 6 之间（这是量化的那条下界；项目的实际取值是
`K=20`、`T=10`，见 §4.7）。`DESIGN.md` 的"50 步 ≈ 7.1e-4 = 6 格"正是
`1e-4·√50`，两处口径一致。**UNVERIFIED**：真实 `G̃` 的符号相关性没测过；同号时 `|Σ| = ηK`，
下界更松；强抵消时更紧。

### 5.3 上界：基能撑多久

**秩不构成上界。** `R` 是 `r×n`，`P R` 对任意大的 `R` 都精确可表示，所以"攒太多、秩装不下"是错的
（`05` 定理 8.1）。真正的上界是基腐坏：`T` 步内 `P` 不变，转出子空间的部分被丢掉。

这一条现在有**直接测量**（`research/m1/REPORT.md` §12.3）：拿 step t−1 拟合的 rank-32 基去捕获
step t 的能量，GDN 三层只有 **0.20–0.40**（oracle 0.995），L3（full attention）反而稳在
0.81–0.97。**一步陈旧就丢掉 60–80% 的能量**，所以区间末的 `χ` 在 GDN 层很快就到 0.6–0.8：

```text
一步陈旧：capture 0.20–0.40（GDN）→  χ ≈ 0.6–0.8                  (8)
```

GUM 外推出来的 `K ≤ 14`（survey §3.9）因此是**乐观的**——不是错，而是它假设了"20 步内缓慢腐坏"，
我们测到的是"一步就腐坏"。

结论：**没有一个"约免费"的 `T`**。本项目的做法是 `T=10`（50 步的 rank 实验跑 5 次刷新），并用端到端
CE 证明这个时程上 rank 不影响 loss（§1.3）。更长的 `T` 更快（§4.7 的表），但**没有任何证据**
说它安全。

### 5.4 EF 拆掉下界，拆不掉上界

下界存在的唯一理由是"小于一格的更新被舍掉且残差不被记住"。EF 把 `e = W_tmp − Q(W_tmp)` 留在
`M` 里（ECO 规则，survey §7.2），下次折叠的目标包含它：

```text
无 EF： Δ = 0.83q → 折成 0 或 1q，误差 ±0.83q，永不补偿
有 EF： Δ = 0.83q → 折成 1q，残差 −0.17q 留到下次，长期平均正确
```

所以**有 EF 时式 (7) 的下界不再约束 `K`**。剩下的约束只有两条：基腐坏（§5.3，一步就掉 60–80%）
与刷新成本（§4.7：每层 11.72 s，40 层总额待拆分）。**EF 买到的是"`K` 不必再受量化限制"，
不是"`K` 可以随便大"**——
上界还在，而且在 GDN 层很紧。

**这就是 GaLore、`R`、EF 必须一起出现的原因**：GaLore 给高精度累加器，`R` 给"小于一格也能攒"的
容器，EF 给"折掉的部分不丢"的机制。缺一个，`K > 1` 都不成立。

**「K ≥ 25 约免费」是错的。** 它只对折叠的 ALU 成立：折叠内核是 4.1–6.6 ms（§4.6），摊到任何
合理的 `K` 上都可以忽略。但它既不描述你付的钱（刷新步是 **11.72 s/层**），也不描述你丢的东西
（25 步陈旧的基在 GDN 层已经把它该抓的能量丢掉大半）。真实的取舍在 `T` 上，
而且是被 SVD 成本卡住的（§4.7）。

## 6. 误差反馈必须，SR 与 RTN 不必

`kernels/quant_scheme_decision.py`：`1024×2048`，2000 步，`K=25`（折 80 次），梯度
`(w−w*)+噪声`，Adam 式归一化，指标是**到最优点的相对距离**（越低越好）。四个 lr 的平均
（`kernels/quant_scheme_decision.json`）：

| 方案 | 平均 | 超出 bf16 |
|---|---|---|
| bf16（地板） | **18.495%** | — |
| **rtn + EF** | **18.514%** | **+0.019 pp** |
| **sr + EF** | **18.536%** | +0.041 pp |
| 纯 sr | 18.903% | +0.408 pp |
| 纯 rtn | 19.280% | +0.785 pp |

**EF 是有效成分**：纯 RTN 差 0.785 pp，加 EF 只差 0.019 pp，回收 **97.6%**（SR 回收 90%）。
**EF 之后 SR 与 RTN 只差 0.022 pp**，在单 seed 噪声内。所以"必须 SR"在本项目指标上不成立——
survey §11 的 SR 推荐来自 Q-GaLore 的 7B 实验，不是我们的数据。

机制：**RTN 有偏、SR 有噪、EF 有记忆。** RTN 的误差与更新方向反相关（`Q(x+Δ)=x` 时 `e=−Δ`，
整个更新被丢掉），是系统性偏置；SR 把它换成零均值方差；只有 EF 改变误差的**结构**，
把偏置变成有界延迟。

**低 lr 端才是分水岭**（同一 JSON，按 lr 拆）：

| lr | bf16 | rtn | sr | rtn+EF | sr+EF |
|---|---|---|---|---|---|
| 3e-4 | 26.628% | 26.638% | 26.659% | 26.632% | 26.648% |
| 1e-4 | 15.347% | 15.418% | 15.482% | 15.367% | 15.384% |
| 3e-5 | 8.475% | 8.851% | 9.212% | 8.516% | 8.556% |
| **1e-5** | **23.528%** | **26.214%** | 24.259% | **23.542%** | 23.558% |

`lr=1e-5`（余弦尾巴，`|ΔW|/q = 0.083`）时纯 RTN 差 **2.69 pp（相对 11%）**，SR 差 0.73 pp，
EF 只差 0.014 pp。这正是式 (7) 下界在真实训练里的表现，也解释了 survey §3.20 说的
"SR 在低 lr 下停滞"：不是 SR 不好，而是**任何无记忆的舍入在 `|ΔW| ≪ q` 时都会失效**。

**一个已修复的实验缺陷，以及修复后的结论。** `bench/foldnoise.py` 的 `k` 循环（第 98 行）
**在循环体里从未被使用**：折叠次数固定 `folds = 20`（第 103 行），每次折一个 `lr` 大小的 `dW`。
所以"折叠间隔 10/50/200 对误差几乎没有影响"的三列是**同一次计算的三次重复**，该结论作废。

正确模型（`bench/foldnoise_k.py`）：固定总步数 600，每 `k` 步把期间累积的 `dW` 折一次，
因此 `k` 决定**折叠次数**。int8、group 32、`lr=1e-4`、真实 `σ_W=6.14e-3`：

| 折叠次数 | 1 | 3 | 12 | 60 |
|---|---|---|---|---|
| int8，无 EF | 0.73% | 1.03% | 1.86% | **4.03%** |
| **int8，装 EF** | **0.73%** | **0.73%** | **0.73%** | **0.73%** |
| int4，装 EF | 13.26% | 13.26% | 13.26% | 13.26% |

两个结论：
1. **不装 EF 时误差随折叠次数增长**（约 `folds^0.4`，比 `√folds` 略慢：实测/预测比值
   0.82→0.71 递减），60 次折叠比 1 次差 **5.5 倍**。所以折叠间隔**确实有影响**。
2. **装了 EF 之后误差与折叠次数完全无关**，被钉在"单次折叠"的水平（0.73%）。
   这才是 EF 最值钱的地方：它把**精度**和**折叠频率**解耦，于是 `K` 可以纯粹按吞吐与
   rank 可表示性来选。int4 的 13.26% 在任何 `K` 下都救不回来。

**注意本实验没有建模 rank 截断**：它折的是精确累积的 `dW`。而"rank-r 能否表示累积更新"其实不是
约束（`05` 定理 8.1：`P R` 对任意 `R` 都精确可表示）。真正的上界是**基陈旧**，它现在已有直接测量
（§5.3：GDN 层一步就掉 60–80%），所以 `K`/`T` 不能靠"折叠便宜"来定。

> **补记（rank 结论：从谱阈值改成 loss 平价）。** 本文 §1 的 r=64 是按 GaLore 原文「rank 取 min-dim 的
> 25%」推出来的，属于**未经测量**的比例外推。
>
> **为什么 rank 低（代数，保留）：** `dW = Σ_t dY_t x_tᵀ` 有精确的两项正交分解
> `n·ȲX̄ᵀ + Σ_t δ_t ξ_tᵀ`，第一项秩 1 且能量按 `n²` 增长。所以单步 `dW` 本来就近似秩 1，
> 熵不是 rank 的原因（`research/rank/MECHANISM.md`）。这条解释的是"**为什么可以低**"，
> 不是"**为什么选 16**"——后者必须实测。
>
> **为什么选 16（验收）：** held-out CE 平价，50 步、只改 `--rank`：r=16 / 32 / 64 =
> 4.2568 / 4.2525 / 4.2625，最大差 **0.010 nats** < **0.014** 噪声地板（§1.3，`runs/M1/rankfixed/`）。
> 谱代价是真的、要一起说：r=16 的 p10 捕获 **0.927–0.971**、中位 0.985–1.000，最差层有 16–60% 的
> 单步低于 0.99（`research/m1/REPORT.md` §12.1）。
>
> **一条被作废的规则：** 「每层 p10 ≥ 0.99」在装得下的 rank 上**无解**（要 r=128，状态 17.45 GB）。
> 它是在死专家 `PR ≈ 1` 的画面上校准的，而那个画面是 RMSNorm 的 bug。旧读数 `PR(dW)` 1.02–1.04、
> 活专家 1.0037–1.0087、`|cos| = 1.0000` 因此仍标 **待重测**（① 取样是专家 0–7，在 L0 拿
> **0/16384** 个路由，零矩阵的 `PR` 恒为 1.0；② pre-fix norm），**但它们已经不再是决策依据**。
>
> **注意力**仍是另一个物种（`PR(q_proj)` 4.09、`PR(o_proj)` 2.25，同样 pre-fix、待重测），
> 所以 r=256 是**保守分配**（1.43 GB），不是测量结论。
>
> 本节其余内容（状态怎么算、为什么必须折叠、三个区怎么分）不受影响。证据：
> `research/m1/REPORT.md` §12（rank）、`research/rank/{SPECTRUM,MECHANISM}.md`（分解与熵的实验）。

## 7. 诚实的局限

1. **专家 r=16 只有 `min-dim` 的 1.6%，远低于 GaLore 验证点的 25%**（survey §4.3）。我们不靠这个比例，
   靠端到端 CE 平价（Δ ≤ 0.010 nats）——但这只在 50 步、这份模型 + 这份语料上成立，
   更长的训练没有排除低秩误差的缓慢累积（UNVERIFIED）。
   survey §7.5 的"翻倍 r 减半误差"是 `σ_i ∝ i^{-1}` 的预测，**不是测量**。
2. **没有公开的 GaLore-on-MoE 结果。** GaLore 2 全文 0 次提到 MoE（survey §3.2）。最近的 MoE 证据
   是 ECO（2.1 B SmoE、DeepSeek-MoE-16B INT4）与 SkewAdam（6.78 B、82 M tokens）。我们是外推。
3. **子空间投影 EF 丢掉 93.75%**（`1−r/m`，r=64, m=1024）。ECO 的精确规则要 `m×n` 动量，
   我们只有 `r×n`。这是**我们的设计，不是论文的**，失败模式清楚：被丢掉的方向若之后回到基里，
   那部分误差已经没了。
4. **基必须来自梯度 SVD——这一点已经修好，但只在 1-block/四层上验证过。** 旧版 `P` 是
   `randn/sqrt(m)` 初始化且永不刷新（旧版 `ExpertStore.__init__`），跑的是随机投影；现在 `--basis svd`
   是默认，`P` 来自按专家捕获的 `dW` 的 SVD + QR，`‖PᵀP−I‖_F` 从 0.60–2.11 降到 3.6e-6~8.9e-6。
   刷新时我们选**携带**：`M' = P'ᵀPM`、`V' = [(P'ᵀP)⊙(P'ᵀP)]V`、`t` 不变（`T=10` 很短，重置的
   10 步冷启动占比不小）——这个选择还没有在长跑上验证。刷新本身是**一阶成本**（§4.7：每层
   11.72 s，40 层总额待拆分），不是可以忽略的簿记。
5. **状态账本必须含 `R`，且 dtype 要统一。** `DESIGN.md` 的 8.05 GB、survey 的 6.38/7.38 GB 都只算
   `P,M,V`；按式 (2) 的真实四项是 **r=16 → 2.18 GB、r=64 → 8.72 GB**。当前 `train/` 用 fp32 存
   `P,R,m,v`，同口径 r=16 是 7.05 GB，上 40 层前必须换 dtype（§1.2）。
6. **基陈旧的速率现在有数了，但它只覆盖 1 步。** 用 step t−1 的基捕获 step t：GDN 层 0.20–0.40、
   L3 0.81–0.97（§12.3）。我们**没有** 2–10 步的曲线，所以 `T=10` 是"已知 1 步很差、端到端 CE 还
   可以"的选择，不是从曲线外推出来的最优值（UNVERIFIED）。

## 8. 一个可以手算的例子

某专家某通道的一个元素：`W = 0.0123`（约 `2σ_W`），通道 `absmax = 1.535e-2`，

```text
s = absmax/127 = 1.209e-4 ,  q = s = 1.209e-4 ,  q/2 = 6.04e-5
```

### 8.1 一步 Adam

第一步 `M=V=0`，偏差修正给 `M̂ = G̃`、`V̂ = G̃²`，所以 `D = sign(G̃)`。设 `G̃ = −3.1e-3`，
则 `D = −1`，`ΔW = −ηD = +1e-4 = 0.827q`。`R` 的对应元素加 `1e-4`；`P R` 是 64 项求和，
但整矩阵秩 ≤ 64——这是 GaLore 与"逐元素独立累加"的唯一区别。

### 8.2 一步折叠

```text
W_tmp = 0.0123 + 1e-4 = 0.0124 ;   W_tmp/s = 102.59
RTN:  code 103 → deq 0.012449 ;  误差 = −4.9e-5 (−0.41q，在 ±q/2 内)
SR :  以 0.59 进到 103，0.41 留在 102
EF :  e = −4.9e-5 存进 M，下次目标包含它
```

**关键**：`ΔW = 0.827q` 被折成 **1.0q**（过冲 0.173q）。下一次若还是 +0.83q，又从 103 格到 104 格，
**每次都过冲**。EF 把每次过冲记下来，累积到一格时抵消。

### 8.3 与实测对账

`K=25`：`|ΣΔW| = 1e-4·5 = 5e-4 = 4.14q`；RTN 误差 ≤ 0.5q，相对累积更新 12%，相对权重 0.98%。
`bench/foldnoise.json` 的 int8 g32 RTN 在 20 次折叠后是 **2.53%**（`int8_g32_lr0.0001_k50_sr0` = 0.02532）：
单次折叠的 RMS 是 `q/√12 = 0.289q`，
相对 `σ_W` 是 `0.289·1.209e-4/6.14e-3 = 0.57%`；20 次独立折叠 `0.57%·√20 = 2.55%`，吻合到 1%。
**这验证了两件事**：折叠误差是随机游走，不是 `DESIGN.md` 说的"有界滞后 ≤ 半个台阶"；
`foldnoise.py` 的误差尺度与实测一致（再次提醒：它的 `k` 没生效，2.53% 对应"每步折"）。

## 本篇要点

1. 全秩 Adam 在专家上要 257.7 GB 矩 + 64.4 GB 权重 = 322.1 GB，是 60 GB 的 5.4 倍；8-bit Adam
   仍要 64.4 GB。**只有低秩投影能进 20.8 GB。**
2. 论文式 `2rn·4 + mr` 在 r=64 是 15.44 GB；本文口径（`P` int8 + `R` bf16 + `m,v` 8-bit）是
   **8.72 GB**，占预算 41.9%；r=16 是 **2.18 GB**。r=128（17.45 GB）放不下。
3. 早期账本的 2.68 / 5.37 / 10.74 / 21.47 混了 `down_proj` 朝向和 dtype 口径；
   **做预算统一用式 (2)：`r × 136.313 M·B`**。
4. r=64 比 r=32 多吃 4.36 GB host（r=16 → 2.18，r=64 → 8.72）；**rank 的决定因素是端到端 CE
   （Δ ≤ 0.010 nats），不是谱阈值**——谱阈值「p10 ≥ 0.99」要 r=128，装不下。
5. 折叠 ALU 是 4.1 ms / `gate_up` 半区（整层 ≈6.6 ms，2.61× 拷贝，100% 码一致；**仅运行时打印**）；
   **但它不是被付的那一项**：一次刷新步（一层）是 11.72 s，折叠内核只有毫秒级。
6. `|ΔW|/q = 0.83`；量化给 `K ≥ 1.45α²`，基腐坏在 GDN 上一步就掉 60–80%——**EF 拆掉下界，
   拆不掉上界**。所以"K ≥ 25 约免费"是错的：`K=20` 是死代码，真实节奏是 `T=10` 刷新顺带折一次。
7. 刷新是**一阶成本**，但**一次刷新步只刷一层**：实测 11.72 s/层，`40 × 11.72 / T` 在 T=100 也是
   4.7 s/步（含诊断的上界，拆分在跑）。杠杆是换只做 bmm 的 SVD 算法，不是调 T。
8. EF 把纯 RTN 的 0.785 pp 差距收到 0.019 pp（97.6%）；之后 SR 与 RTN 只差 0.022 pp。
   **必须 EF，不必 SR**；低 lr 的 2.69 pp 才是分水岭。
9. 六个局限：1.6% vs 25%、无 MoE 先例、投影 EF 丢 94%、SVD 基只在 1-block/四层验证过、
   dtype 未统一（fp32 → 7.05 GB）、`foldnoise` 的 `k` 未生效。
