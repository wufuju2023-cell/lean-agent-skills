# 04 · AdamW：推导、内存、以及它为什么和 int8 主权重打架

**这一篇讲什么.** 前三篇讲的是"参数怎么存、怎么算"。这一篇讲"参数怎么改"。AdamW 是现在训练大模型的默认优化器，但它经常被当成一个黑盒：为什么除以二阶矩、`1-β^t` 那个偏差修正到底在修什么、weight decay 为什么必须"解耦"、以及最关键的——**Adam 每一步到底把权重改了多少**。最后这个问题是本项目全部设计的枢纽：它的答案是"约等于学习率 `η`"，而 `η = 1e-4` 与 int8 的量化台阶 `1.2e-4` 是同一个量级。于是"直接量化存权重"这条路在数学上就走不通，必须引入一个高精度的残差累加器。这一篇把这条链子从头推一遍。

**读完你会知道.** 为什么二阶矩归一化让更新对梯度的整体缩放不变（推导三行）；`E[M_t] = (1-β₁^t)E[G]` 是怎么来的、为什么偏差修正必须除以 `1-β₁^t`；AdamW 的解耦衰减与 L2 正则差在哪（差在 `1/√v̂` 这个因子）；32.21 B 专家的优化器状态到底多少 GB（257.7 GB，不是 287.6——后者是全模型 35.95 B）；为什么 `|ΔW| ≈ η`、为什么 `η/q = 0.83` 是"量化主权重"这件事的核心数字；以及在 `|ΔW|/q ≫ 1`、`≈ 1`、`≪ 1` 三个区间里分别会发生什么（含一个可以精确预测的"存储冻结"阈值，实测正好落在那里）。

> 记号沿用 `00-notation.md`：`W` 权重 `m × n`，`G = ∂L/∂W`，`η` 学习率，`β₁, β₂` 矩衰减系数，`ε` 分母平滑项，`M, V` 一阶/二阶矩，`M̂, V̂` 偏差修正后的矩，`t` 步数（从 1 开始），`s` 量化尺度，`K` 折叠间隔，`T` 基刷新间隔，`P R` 低秩修正。

> **数字出处约定.** 〔`路径`: `键`〕= 落盘 JSON；〔`路径` §n〕= 报告正文；〔推导〕= 本篇自算（§6 脚本）；〔UNVERIFIED〕= 找不到、不猜。

## 1. 从 SGD 到 AdamW

### 1.1 为什么不能只用一阶

最朴素的更新是 `W ← W - η·G`。它有两个致命问题：

1. **每个坐标需要的步长不一样**。同一个矩阵里，有的元素梯度长期是 `1e-2`，有的长期是 `1e-6`；用同一个 `η`，前者震荡、后者不动。
2. **步长会被梯度的整体尺度绑架**。把损失乘 100，`G` 也乘 100，同一个 `η` 立刻发散。

Adam 的两个矩就是为这两件事准备的：一阶矩 `M` 提供方向（动量，平滑噪声），二阶矩 `V` 提供**每个坐标自己的步长**。

```text
M_t = β₁·M_{t-1} + (1-β₁)·G_t          （一阶矩：梯度的指数滑动平均）
V_t = β₂·V_{t-1} + (1-β₂)·G_t²         （二阶矩：梯度平方的指数滑动平均，逐元素）
```

### 1.2 二阶矩归一化 = 尺度不变性

看 `M/√V` 这个比值。若把梯度整体乘一个常数 `c`（等价于把损失乘 `c`）：

```text
G → cG  =>  M → cM  =>  V → c²V  =>  M/√V → (cM)/(c√V) = M/√V
```

**不变。** 这就是"对梯度的整体缩放不敏感"的严格含义，也是 Adam 敢用固定 `η` 的原因。逐坐标看：若某个坐标的梯度长期是 `g`，则 `M ≈ g`、`V ≈ g²`，比值 `≈ sign(g)`——**步长与梯度大小无关，只与方向有关**。这句话在 §3 会变成一个非常硬的结论。

### 1.3 偏差修正的推导

`M_0 = V_0 = 0`，所以前几步的矩被 0 拉低了。展开递推：

```text
M_t = (1-β₁)·Σ_{i=1..t} β₁^{t-i}·G_i
```

两边取期望。若梯度平稳（`E[G_i] = ḡ` 对所有 `i`）：

```text
E[M_t] = (1-β₁)·ḡ·Σ_{i=1..t} β₁^{t-i}
       = (1-β₁)·ḡ·(1-β₁^t)/(1-β₁)
       = (1-β₁^t)·ḡ
```

所以 `M_t` 的期望是真实一阶矩的 `(1-β₁^t)` 倍——**第 1 步只有 0.1 倍**（`1-0.9 = 0.1`），第 10 步 0.65 倍，第 100 步 0.99997 倍。修正就是除回去：

```text
M̂_t = M_t / (1-β₁^t)          V̂_t = V_t / (1-β₂^t)
```

同样可得 `E[V_t] = (1-β₂^t)·E[G²]`。注意一个不对称：`1-β₂^t` 在 `t=1` 时是 `0.001`，所以 `V` 的"预热"比 `M` 慢得多——这也解释了 §5 里"重置 `t` 但不重置矩"会造成多大的爆炸。

### 1.4 解耦权重衰减

L2 正则把 `λW` 加进梯度：`G ← G + λW`，然后整个 `G` 走进 `M/√V`。于是衰减项被 `1/√V̂` 缩放：

```text
L2 的有效衰减 ≈ -η·λW/√V̂          <- V̂ 大的坐标衰减被压小，V̂ 小的被放大
```

`V̂` 大的坐标（梯度大）衰减被压小，`V̂` 小的坐标衰减被放大——**衰减强度变成了梯度的函数，这不是我们想要的**。AdamW 的做法是把衰减从梯度里拿出来，直接乘在参数上：

```text
AdamW:   W ← W·(1 - η·λ)  -  η·M̂/(√V̂ + ε)
```

### 1.5 完整更新式

```text
每步 t:
  M ← β₁·M + (1-β₁)·G
  V ← β₂·V + (1-β₂)·G²
  M̂ ← M/(1-β₁^t) ;  V̂ ← V/(1-β₂^t)
  W ← W·(1 - η·λ) - η·M̂/(√V̂ + ε)
```

本项目的超参：`η = 1e-4`，`β₁ = 0.9`，`β₂ = 0.999`，`ε = 1e-8`〔`runs/B/REPORT.md` §3 的训练协议：`lr 1e-4`；`train/block_train.py` 的默认值〕。

## 2. 内存：`2mn` 的算术

`M` 和 `V` 与 `W` 同形状，每个元素 4 字节（fp32）。所以**每个参数**的优化器状态是

```text
2 × 4 B = 8 B/参数
```

对 35.95 B 参数的全模型：

```text
35.952e9 × 8 B = 287.6 GB          <- DESIGN.md §0 的 287.6 GB，口径是全模型
```

只算 32.21 B 个专家参数：

```text
32.212e9 × 8 B = 257.7 GB          <- 专家部分；257.7 / 60 = 4.3 个内存
```

> **口径校正**：`287.6 GB` 对应的是 **35.95 B**（全模型）而不是 32.21 B（专家）。`32.21 B × 8 B = 257.7 GB`。两个数都出现在本项目文档里，混用会差 12%。本篇一律分开写。

8-bit Adam 把每个矩压到 1 字节：

```text
2 × 1 B = 2 B/参数
全模型 35.952e9 × 2 = 71.9 GB       <- DESIGN.md §3.1 的 71.9 GB
专家   32.212e9 × 2 = 64.4 GB       <- 仍然 > 60 GB
```

**关键点**：`DESIGN.md` §3.1 说的"8-bit Adam 也不行"是**在 int8 主权重已经存好之后**算的——它只计矩的 2 B/参数，因为主权重就是那 34.2 GB 的 int8 存储。即使如此，64.4 GB 仍然装不进 60 GB，而且这还没算激活（8.05 GB，`DESIGN.md` §3.2 的分配值）和注意力（2.86 GB）。

所以本项目的结论是：**8-bit Adam 救不了，只有低秩投影能救**——把 `m × n` 的矩换成 `r × n` 的矩，状态从 257.7 GB 降到 GB 级：按 `STATE.md` §6 的口径（`P` int8 + `R` bf16 + `m,v` 8-bit，`r × 136.313 M·B`），r=32 是 **4.36 GB**、r=16 是 **2.18 GB**（`06` §1.2）。注意早期文档的 8.05 / 6.03 GB 是 `r × 41.94 M × 4 B` 的旧口径（`down_proj` 朝向错、dtype 混杂），**不要再用**。`05-galore-math.md` 讲为什么这样做不损失收敛性，本篇只讲它为什么是"不得不"。

## 3. 更新幅度：`|ΔW| ≈ η`

### 3.1 推导

§1.2 已经得到：单个坐标上 `M̂/√V̂ ≈ sign(g)`，只要该坐标的梯度方向稳定（信噪比高）。于是

```text
|ΔW| ≈ η · 1 = η
```

更精确一点。设梯度是"均值 `ḡ` + 噪声 `σ`"，则 `M̂ ≈ ḡ`、`V̂ ≈ ḡ² + σ²`，于是

```text
|M̂|/√V̂ = |ḡ|/sqrt(ḡ² + σ²) = SNR/sqrt(1 + SNR²)    （SNR = |ḡ|/σ）
```

- `SNR → ∞`（方向完全稳定）：比值 → 1，`|ΔW| = η`。
- `SNR = 1`：比值 = 0.707，`|ΔW| = 0.707η`。
- `SNR → 0`（纯噪声）：比值 → 0，几乎不动。这是 Adam 的自我保护：它不会放大噪声。

所以 `|ΔW| ≈ η` 是**上界**，实际在 `0.5η–1η` 之间。本项目的两个实验脚本都直接用了这个近似：`bench/foldnoise.py` 用 `dW ~ N(0, lr)`、`kernels/quant_scheme_decision.py` 用 `step = -lr·g/(|g|.mean()/3)`（脚本注释："Adam-normalised step ~ lr"）。`DESIGN.md` §5.3 也直接用 `|ΔW| ≈ lr ≈ 1e-4`。

### 3.2 与 int8 台阶的比值：0.83

把 `01-numbers.md` §3.3 的台阶拿过来（组 32、`σ_W = 6.14e-3`、`absmax ≈ 2.36σ`）：

```text
q = 2·2.36·6.14e-3/255 = 1.14e-4      （01 篇按实测 0.535% 反推的值）
q = 2·2.5·6.14e-3/255  = 1.20e-4      （DESIGN.md §5.3 用的取整值）

η/q = 1e-4/1.20e-4 = 0.83             <- DESIGN.md §5.3 的 0.83
η/q = 1e-4/1.14e-4 = 0.88             <- 用 01 篇的精确台阶
```

**`0.83` 就是这个项目里最重要的一个数**：Adam 走一步的距离，比 int8 的一个格点还小。这意味着"把 `W - η·g` 写回 int8 存储"这个动作，在大多数坐标上**根本不会改变存储的值**——`round((W - ηg)/s)` 与 `round(W/s)` 是同一个整数。

### 3.3 三个区间

设折叠间隔 `K`，则折叠前累积的更新是随机游走 `√K·η`（各步方向不相关）。判据是它和半个格点 `q/2` 的关系：

| 区间 | 条件 | 物理后果 | 本项目的实例 |
|---|---|---|---|
| `\|ΔW\|/q ≫ 1` | `η ≫ q` | 量化噪声可忽略；存储每步都在动 | 本项目不出现（`η/q` 最大 0.88） |
| `\|ΔW\|/q ≈ 1` | `η ≈ q` | 有噪声但还能跟踪，误差约 `q/√12` 量级 | **本项目 int8：0.83** |
| `\|ΔW\|/q ≪ 1` | `√K·η < q/2` | **存储冻结**：折叠后码值不变，更新全丢 | int4：`η/q = 0.05` |

**冻结阈值可以精确算出来**：`√K·η < q/2`，代入 `K = 25`（`kernels/quant_scheme_decision.py` 的 `fold_every`）得 `η/q < 0.5/5 = 0.1`。作为对照，四层生产配置是 `K = 20`、`T = 10`（`train/m1_run.py` 的默认值）、`η/q = 0.83`，`√20 × 0.83 = 3.7 ≫ 0.5`——**离冻结区有 7 倍余量**；但如果每步折叠（`K=1`），`0.83 > 0.5` 只有 1.7 倍余量，这就是"必须有残差累加器"的定量表述。

实测正好在这里拐弯（`kernels/quant_scheme_decision.json`，指标是到最优点的相对距离，bf16 与 int8-RTN 的差）：

| `lr` | `\|ΔW\|/q` | bf16 | int8 + RTN | 惩罚 |
|---|---|---|---|---|
| 3e-4 | 0.77 | 26.628% | 26.638% | **+0.010 pp** |
| 1e-4 | 0.26 | 15.347% | 15.418% | **+0.070 pp** |
| 3e-5 | 0.077 | 8.475% | 8.851% | **+0.376 pp** |
| 1e-5 | 0.026 | 23.528% | 26.214% | **+2.686 pp** |

〔`kernels/quant_scheme_decision.json`: `bf16_lr*` / `rtn_lr*`。该脚本的 `q` 由它自己的合成目标 `σ = 0.02` 定出（`q = 3.92e-4`），所以 `|ΔW|/q` 一列不能与真实权重上的 `q = 1.2e-4` 直接换算——但冻结判据的形式与比值区间是一样的。〕

前三行惩罚在 0.01–0.38 pp 之间缓慢增长；跨过 `η/q ≈ 0.05`（低于 0.1 的阈值）后突然跳到 2.69 pp——**7 倍**。这不是拟合出来的，是 `√K·η < q/2` 这条判据预测的位置。同一张表里加误差反馈（EF）后四行全部回到 bf16 水平（`02-quantization.md` §5.2），因为残差累加器把"被冻结的更新"存到了别处。

对 int4：`η/q = 1e-4/1.93e-3 = 0.052`，`√25 × 0.052 = 0.26 < 0.5`，**从第一步就落在冻结区**。这解释了 `01-numbers.md` §6 的 12.33%——不是"噪声大"，是"存储根本不跟着走"。

## 4. 矩是"按坐标"的

这一节的结论在 `05-galore-math.md` 里会变成一个定理的前提，所以要说精确。

Adam 的每一步都是**逐元素**运算：

```text
M_ij ← β₁M_ij + (1-β₁)G_ij
V_ij ← β₂V_ij + (1-β₂)G_ij²
W_ij ← W_ij - η·M_ij/√V_ij
```

下标 `(i,j)` 是**当前坐标系**里的坐标。如果换一组基（比如 `W = P R`，`P` 是 `m × r` 的正交列基），坐标就变成 `R` 的元素，而 `M, V` 是在旧坐标里累积的。**它们不能通过一个旋转搬到新坐标**：

```text
M' = PᵀMP     （这是"把矩阵转过去"）
但 Adam 要的是 M' 的逐元素函数：f(M') = M' / sqrt(V')
而 f(PᵀMP) ≠ Pᵀ f(M) P        （逐元素函数与旋转不对易）
```

数值例子（§6 脚本，3×3、旋转 0.6 rad）：`‖U' - R U Rᵀ‖_F / ‖U'‖_F = 0.354`——**差 35%**，不是小量。

三句话总结：

1. `M`、`V` 不是"这个矩阵的某种内在属性"，而是"这个矩阵在**这组坐标下**的属性"。
2. 换基之后旧动量**没有**正确的搬运方式；能选的只有"丢掉重来"或"近似搬过去"，两者都要明说。
3. `V` 是一个**对角预条件子**（只保留逐坐标的方差，丢掉坐标间的相关）。换基后真实的预条件子不再是 diag，所以任何搬运都是近似。

## 5. 投影子空间里的偏差修正

到了 GaLore，矩活在 `r × n` 的投影空间（`R` 的坐标）里，而不是 `m × n`。这时 `t` 有两种语义，选错会有可算的后果。

**情形 A：刷新基时把矩一起清零，`t` 也清零。** 第一步的 `(1-β₁^1) = 0.1`、`(1-β₂^1) = 0.001`，修正后 `M̂/√V̂ = sign(g)`，步长正好 `η`。干净，但每 `T` 步丢掉一次动量；`M` 的记忆长度是 `1/(1-β₁) = 10` 步，所以 `T ≫ 10` 时这个瞬态只占 `10/T` 的时间（`T = 200` → 5%）。

**情形 B：清零矩但保留 `t`。** 第 `T+1` 步时分母 `1-β₁^t ≈ 1`、`1-β₂^t ≈ 1`，于是

```text
M̂/√V̂ = (1-β₁)·g / sqrt((1-β₂)·g²)
      = (1-β₁)/sqrt(1-β₂) · sign(g)
      = 0.1/0.0316 · sign(g)
      = 3.16 · sign(g)
```

**第一步的步长是 `3.16η`，超调 3.2 倍**，每 `T` 步来一次。这不是小效应：它等于周期性给权重一个 3 倍大的踢腿。

**情形 C：不清零矩、也不清零 `t`**（把旧动量当新坐标的动量用）。§4 已经说明这在数学上是错的（差 35% 量级），而且 `V` 的分母会带着旧坐标的尺度，等效于给每个新坐标一个错误的步长。

**本项目的选择**：刷新基之前**必须先折叠**（把 `P R` 写进 `Ŵ`，`R` 清零），然后 `t` 跟着重置——这正是 `05-galore-math.md` 里那条"可表示性定理"要求的顺序（先折叠、再换基），本篇只负责说明"`t` 为什么必须跟着走"。

## 6. 复现脚本

```python
"""04 篇：AdamW 对齐 torch、内存账本、|dW|/q 三区间、矩的坐标依赖。CPU 即可。"""
import numpy as np
import torch

torch.manual_seed(0)

# ---------------- 1. AdamW: 20 行 ----------------
class AdamW:
    def __init__(self, params, lr=1e-3, betas=(0.9, 0.999), eps=1e-8, wd=0.01):
        self.p, self.lr, (self.b1, self.b2), self.eps, self.wd = list(params), lr, betas, eps, wd
        self.m = [torch.zeros_like(x) for x in self.p]
        self.v = [torch.zeros_like(x) for x in self.p]
        self.t = 0

    @torch.no_grad()
    def step(self):
        self.t += 1
        c1, c2 = 1 - self.b1 ** self.t, 1 - self.b2 ** self.t
        for x, m, v in zip(self.p, self.m, self.v):
            g = x.grad
            m.mul_(self.b1).add_(g, alpha=1 - self.b1)              # 一阶矩
            v.mul_(self.b2).addcmul_(g, g, value=1 - self.b2)       # 二阶矩
            x.mul_(1 - self.lr * self.wd)                           # 解耦衰减
            x.addcdiv_(m / c1, (v / c2).sqrt().add_(self.eps), value=-self.lr)

    def zero_grad(self):
        for x in self.p:
            x.grad = None

n = 64
a = torch.randn(n)
Q, _ = torch.linalg.qr(torch.randn(n, n))
H = Q @ torch.diag(torch.logspace(-2, 2, n)) @ Q.T               # 各坐标尺度差 1e4
w1 = torch.zeros(n, requires_grad=True)
w2 = w1.detach().clone().requires_grad_(True)
o1, o2 = AdamW([w1], lr=3e-3, wd=0.01), torch.optim.AdamW([w2], lr=3e-3, weight_decay=0.01)
for _ in range(300):
    for w, o in ((w1, o1), (w2, o2)):
        o.zero_grad()
        d = w - a
        (0.5 * d @ (H @ d)).backward()
        o.step()
print(f"== 1. AdamW 从零 vs torch: max|Δ| = {(w1-w2).abs().max():.2e} (要求 <= 1e-6)")

# ---------------- 2. 内存 ----------------
print("== 2. 优化器状态（2mn fp32 = 8 B/参数）==")
for tag, p in (("全模型 35.952B", 35.952e9), ("专家 32.212B", 32.212e9)):
    print(f"  {tag:16s} fp32 {p*8/1e9:6.1f} GB | 8-bit 矩 {p*2/1e9:5.1f} GB")

# ---------------- 3. |dW|/q 与冻结阈值 ----------------
print("== 3. 量化主权重：|dW|/q 扫描 ==")
M2, K2, steps, fold = 96, 384, 2000, 25
target = torch.randn(M2, K2) * 0.02
q = 2 * 2.5 / 255 * 0.02

def run(lr, mode):
    torch.manual_seed(1)
    w, acc, resid = torch.zeros(M2, K2), torch.zeros(M2, K2), torch.zeros(M2, K2)
    code = torch.round(w / q).clamp(-127, 127)
    for t in range(steps):
        g = (w - target) + torch.randn(M2, K2) * 0.01
        step = -lr * g / (g.abs().mean() / 3 + 1e-12)            # 单步 |dW| ~ lr
        if mode == "bf16":
            w = w + step
            continue
        acc += step
        if (t + 1) % fold == 0:
            tgt = code * q + acc + resid
            cn = torch.round(tgt / q).clamp(-127, 127)
            if mode == "ef":
                resid = tgt - cn * q
            code, acc, w = cn, torch.zeros_like(acc), cn * q + (resid if mode == "ef" else 0)
        else:
            w = code * q + acc + (resid if mode == "ef" else 0)
    return ((w - target).pow(2).mean().sqrt() / target.pow(2).mean().sqrt()).item()

print(f"  q = {q:.2e}, 每 {fold} 步折叠；冻结阈值 |dW|/q < 0.5/sqrt(K) = {0.5/np.sqrt(fold):.3f}")
print(f"  {'lr':>7} {'|dW|/q':>7} {'bf16':>7} {'rtn':>7} {'rtn+ef':>7}")
for lr in (3e-3, 1e-3, 3e-4, 1e-4, 3e-5, 1e-5):
    print(f"  {lr:7.0e} {lr/q:7.2f} {run(lr,'bf16')*100:6.2f}% {run(lr,'rtn')*100:6.2f}%"
          f" {run(lr,'ef')*100:6.2f}%")

# ---------------- 4. 矩在坐标里的含义 ----------------
print("== 4. M/√V 与旋转不对易 ==")
M3 = torch.tensor([[1.0, 2, 0], [2, 4, 1], [0, 1, 3]], dtype=torch.float64)
V3 = torch.tensor([[4.0, 1, .5], [1, 2, .3], [.5, .3, 1]], dtype=torch.float64)
th = 0.6
R = torch.tensor([[np.cos(th), -np.sin(th), 0], [np.sin(th), np.cos(th), 0], [0, 0, 1]],
                 dtype=torch.float64)
u = M3 / V3.sqrt()
u_new = (R @ M3 @ R.T) / (R @ V3 @ R.T).sqrt()
print(f"  ||U' - R U R^T||_F / ||U'||_F = {(u_new - R @ u @ R.T).norm()/u_new.norm():.3f}")
```

实测输出：`(1) 2.4e-07`（对齐到 1e-6 以内）；`(2) 287.6 / 71.9 GB` 与 `257.7 / 64.4 GB`；`(3)` 惩罚随 `|dW|/q` 减小单调变大——`7.65 → 2.55 → 0.77 → 0.26 → 0.08 → 0.03` 对应 `−0.36 / +0.33 / +0.89 / +1.54 / +2.45 / +3.33 pp`，而 `rtn+ef` 一列**每行都等于 bf16**；`(4) 0.354`。

## 本篇要点

1. Adam 用 `M/√V` 而不是 `M`：这一步让更新**对梯度的整体缩放不变**（`G → cG` 时比值不变），并让每个坐标有自己的步长。
2. 偏差修正的推导只有一行：`E[M_t] = (1-β₁^t)·E[G]`，所以除回去。`β₂ = 0.999` 意味着 `V` 的预热比 `M` 慢 100 倍。
3. AdamW 的解耦衰减 `W ← W(1-ηλ) - ηM̂/√V̂` 与 L2 的区别：L2 的 `λW` 会穿过 `1/√V̂`，衰减强度变成梯度的函数。
4. 优化器状态是 `2mn` 个 fp32 = **8 B/参数**。全模型 35.95 B → **287.6 GB**；专家 32.21 B → **257.7 GB**（不是 287.6，后者是全模型）；8-bit 矩 → 71.9 / 64.4 GB，仍然 > 60 GB。
5. `|ΔW| ≈ η`（信噪比高时是上界，实际 `0.5η–1η`）。`η = 1e-4` vs int8 台阶 `1.2e-4` → **`η/q = 0.83`**：Adam 一步比一个格点还小。
6. 三个区间：`≫1` 量化噪声可忽略；`≈1` 本项目所处，误差 `q/√12` 量级；`≪1` **存储冻结**，判据 `√K·η < q/2`（`K=25` 时 `η/q < 0.1`）。实测惩罚在 `0.077 → 0.026` 之间从 +0.38 pp 跳到 +2.69 pp，正好在预测的阈值上。
7. `M, V` 是**按坐标**的：换基后 `f(RMRᵀ) ≠ R f(M) Rᵀ`，数值例子差 35%。所以基刷新时旧动量没有正确的搬运方式。
8. 投影空间里的 `t`：清矩必须同时清 `t`，否则（保留 `t`）第一步步长是 `3.16η`（`(1-β₁)/√(1-β₂) = 0.1/0.0316`）；这就是"刷新前必须先折叠、`t` 跟着重置"的定量理由。
