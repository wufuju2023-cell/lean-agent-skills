# 01 · 数值格式：bf16 / int8 / int4 各自能表示什么

**这一篇讲什么.** 一个数字存进显存或内存时，只占若干个比特，而比特数是有限的，所以"存进去的数"和"算出来的数"永远不完全一样。这一篇从最基础的三件事讲起：浮点数为什么长成"符号 + 指数 + 尾数"这个样子、bf16 的 7 位尾数到底意味着多大的相对误差、int8 / int4 为什么根本不是浮点数而是定点数。然后把这三者放在同一张表里比较，算清"32.21 B 个专家参数各要多少 GB"，最后说明为什么本项目的实测数据把 int4 直接判了死刑。

**读完你会知道.** 为什么 bf16 的 machine epsilon 是 `2^-8 ≈ 3.9e-3` 而不是 `2^-7`；为什么"小于某个值 0.39% 的增量会被丢掉"这句话对 bf16 成立、对 int8 完全不成立；int8 的量化台阶怎么从组内 absmax 算出来、为什么是 `1.2e-4` 这个量级；为什么 int8 的往返误差（0.535%）比 bf16（0.165%）还大、却仍然是唯一可用的主权重格式；以及 int4 的 12.33% 功能误差是怎么来的、为什么任何参数组合都救不了它。

> 符号全部沿用 `00-notation.md`：`W` 是权重矩阵，`m × n`；`s` 是量化尺度；`q_max` 是该格式的正向上界；`Q(·)` / `deq(·)` 是量化 / 反量化算子；`η` 是学习率；`⌊·⌉` 是最近取整。

> **数字出处约定.** 〔`路径`: `键`〕= 仓库里落盘的 JSON 实测值；〔`路径` §n〕= 报告正文里的实测；〔推导〕= 本篇自己算的，脚本在 §7，可当场复跑；〔UNVERIFIED〕= 仓库里找不到、也不猜。

## 1. 计算机为什么必须有"格式"

### 1.1 三个字段

一个浮点数被拆成三段存：

| 字段 | 作用 | 位数多会怎样 |
|---|---|---|
| 符号 (sign) | 正还是负 | 永远 1 位 |
| 指数 (exponent) | 小数点在哪，决定**范围** | 能表示更大/更小的数 |
| 尾数 (mantissa) | 有效数字，决定**精度** | 相邻两个数挨得更近 |

写成公式就是：一个浮点数 = `±1.mantissa × 2^(exponent - bias)`。尾数那一位 `1.` 是隐含的，不占存储，所以"7 位尾数"实际给 8 位有效数字。

### 1.2 范围和精度是一对矛盾

总位数固定时，多给指数一位，范围翻倍，精度减半。这是整个数值格式设计的唯一矛盾：训练里梯度动态范围极大 → 指数多给（bf16）；推理里权重都差不多大 → 尾数多给（fp16）；只要省地方、范围已知 → 干脆不要指数（int8 / int4）。

### 1.3 位布局总表

| 格式 | 总位数 | 符号 | 指数 | 尾数 | 有效位数 | 1.0 处的半台阶 `u` | 最小正规数 | 最大有限值 |
|---|---|---|---|---|---|---|---|---|
| fp32 | 32 | 1 | 8 | 23 | 24 | `2^-24 ≈ 6.0e-8` | `1.2e-38` | `3.4e38` |
| bf16 | 16 | 1 | 8 | 7 | 8 | `2^-8 ≈ 3.9e-3` | `1.2e-38` | `3.4e38` |
| fp16 | 16 | 1 | 5 | 10 | 11 | `2^-11 ≈ 4.9e-4` | `6.1e-5` | `65504` |
| fp8-e4m3 | 8 | 1 | 4 | 3 | 4 | `2^-4 = 6.3e-2` | `2.0e-3`（次正规） | `448` |
| int8 | 8 | 1（补码） | 无 | 无 | 8（固定刻度） | 由 `s` 决定 | 由 `s` 决定 | `127·s` |
| int4 | 4 | 1（补码） | 无 | 无 | 4（固定刻度） | 由 `s` 决定 | 由 `s` 决定 | `7·s` |

**bf16 的全部卖点就在最后两列里**：它和 fp32 共享 8 位指数，所以 fp32 能表示的指数范围它都能表示，`1e-30` 和 `1e30` 都不会上溢/下溢；代价是尾数从 23 位砍到 7 位。换句话说，bf16 是"把 fp32 的小数点后面截掉"，不是"把 fp32 缩小"。

### 1.4 定点不是浮点

`int8` 和 `int4` 没有指数字段。它们表示的是**整数**，要变成实数必须乘一个外部的尺度 `s`：

```text
存进内存的是整数   q ∈ {-128, …, 127}          （int8）
读出来是实数       w ≈ q · s                    （s 是浮点数，另存）
```

所以 int8 的精度**不是**一个固定的相对精度，而是"最大能表示 `127·s`、最小刻度 `s`"。`s` 选多大，完全由量化的那一方决定。这是 int8 和 bf16 最本质的区别，后面 §3、§4 都围绕它展开。

## 2. bf16：8 位指数 + 7 位尾数

### 2.1 machine epsilon 的推导

把 1.0 写成 bf16：

```text
1.0 = +1.0000000 × 2^0        （7 个尾数位全是 0）
```

下一个能表示的 bf16 是

```text
1.0 + 2^-7 = 1.0078125        （尾数最低位置 1）
```

也就是 1.0 附近的**间距**是 `2^-7 = 7.81e-3`。工程上更常用的是"半个间距"，即把一个实数舍入到最近格点时最大可能的相对误差：

`u = 2^-8 = 3.906e-3 ≈ 3.9e-3`。

这就是本篇（以及 `00-notation.md`）所说的 machine epsilon。注意定义差别：IEEE 把 `2^-7` 叫 "machine epsilon"（相邻间距），数值分析教材常把 `2^-8` 叫 "unit roundoff"（半间距）。**两者都合法，差一个 2 倍**；本篇一律用 `u = 2^-8`，因为"误差上界"是它。

### 2.2 具体到本项目的权重

实测的专家权重标准差是 `σ_W = 6.14e-3`（〔`bench/foldnoise.json`: `sigma_W` = 0.0061355〕，取自 `layers.0.mlp.experts.gate_up_proj` 专家 0，形状 `[1024, 2048]`）。它落在哪个二进位区间？

即 `2^-8 = 3.9e-3 ≤ σ_W < 2^-7 = 7.8e-3`，所以这个量级的 bf16 间距是 `2^(-8-7) = 2^-15 = 3.05e-5`，占该数值的 `3.05e-5 / 6.14e-3 = 0.497%`。

**具体含义：给一个 `6.1e-3` 的权重加一个比 `3.05e-5`（约 0.5%）还小的增量，bf16 会把它整个吞掉，权重值不变。** 这不是"误差 0.5%"，是"信息 100% 丢失"——小于半个台阶的增量不是被舍入成有误差的数，而是被舍入成原来的数。

### 2.3 bf16 什么时候会吃掉 Adam 的一步

Adam 的单步更新幅度约等于学习率本身（推导见 `04-adamw.md` §3）：`|ΔW| ≈ η`。取本项目用的 `η = 1e-4`〔`DESIGN.md` §5.3〕，问：多大权重的 bf16 会把这个更新吃掉？

丢步的条件是 `η < u·|w|`，即

```text
|w| > η / u = 1e-4 / 3.9e-3 = 2.56e-2
```

而 `σ_W = 6.14e-3`，所以 `2.56e-2 = 4.2 σ_W`。也就是说：**bf16 主权重只对 4σ 以外的极端大权重丢步**（考虑二进位位置，阈值在 `2.56e-2` 到 `5.1e-2` 之间浮动），矩阵里绝大多数元素每步都能被记录。这是"bf16 主权重在实践中够用"的定量理由，也是它与 int8 的分水岭（§4.1）。

## 3. int8 / int4：定点

### 3.1 仿射量化器

对称量化（symmetric quantization）的定义只有三行：

```text
尺度     s   = absmax / q_max           absmax = max|W_ij| （在某个"组"内，见 02 篇）
量化     q   = clamp(⌊W / s⌉, -q_max, q_max)
反量化   ŵ   = q · s
```

`q_max` 对 int8 是 127，对 int4 是 7。注意 `s` 是用 absmax 定的，所以 `absmax` 那个元素恰好落在 ±127（或 ±7）上，没有截断。

### 3.2 台阶与 RMS 误差

相邻两个格点的距离（台阶，quantization step）是

```text
step = 2 · absmax / (2^b - 1)          b = 位宽
```

对 int8：`step = 2·absmax/255`；对 int4：`step = 2·absmax/15`。

如果被量化的数在 `[-absmax, absmax]` 上均匀分布，舍入误差就均匀落在 `[-step/2, step/2]`，于是

`E[err] = 0`，`RMS(err) = step/sqrt(12) = 0.2887·step`。

但在神经网络权重上**分布不是均匀的，是高斯**。这时误差不是均匀分布，不过有一个很好用的近似：在组内，每个元素看到的台阶是常数（组量化），误差方差仍是 `step²/12`，所以 RMS 误差还是 `step/sqrt(12)`，只是 `step` 由组内 absmax 决定。把 `step` 代进去：

`RMS(err)/σ_W = (2·absmax/q_max) / (sqrt(12)·σ_W)`。

### 3.3 高斯 + 组 absmax 的实际台阶

高斯样本的 absmax 不是 σ，而是"n 个样本最大值的期望"。测出来（`kernels/sweep.json` 的 0.535% 反推，见 §7 脚本）：

| 组大小 | `absmax/σ`（20,000 次抽样） |
|---|---|
| 32 | 中位数 2.30，均值 2.35 |
| 2048 | 中位数 3.58，均值 3.63 |

所以组 32 的 int8 台阶是（用实测 0.535% 反推，得组内 `absmax = 2.36σ`；与上表 2.35 的均值一致）：

```text
step = 2 · 2.36σ / 255 = 0.0185σ
RMS  = step/sqrt(12) = 0.00534σ = 0.534%
```

这正好是实测的 `0.535%`〔`kernels/sweep.json`: `int8_group32_rel` = 0.005346〕。int4 同理：`step = 2·2.36σ/15 = 0.315σ` → `RMS = 9.1%`，而实测静态误差是 `10.24%`〔`bench/foldnoise.json`: `static_int4_g32` = 0.10243〕——同一套算术，差 12%（真实权重比高斯尾巴略厚）。

### 3.4 有效比特数

int8 号称 8 位，但对一个高斯分布**真正用上的位数**没那么多。±1σ 这段（包含 68% 的元素）占整个 `[-absmax, absmax]` 的比例是

`2σ / (2·2.36σ) = 42%`。

也就是 255 个格点里有 `0.42 × 255 ≈ 108` 个落在 ±1σ 内 → 约 `log2(108) = 6.75` 位有效分辨率。bf16 的 8 位有效数字是**相对于每个数自身**的，所以对 `1e-6` 和 `1e-2` 的元素一样好用；int8 的 6.75 位是**整个组的绝对刻度**，组里最小的元素（比如 `0.01σ`）只分到 1 个格点。

这就是"bf16 是相对精度、int8 是绝对精度"的量化说法。

## 4. 三者诚实对比

### 4.1 相对误差 vs 绝对误差

| | bf16 | int8（组 32） | int4（组 32） |
|---|---|---|---|
| 误差性质 | 相对（每个数 `u·\|w\|`） | 绝对（每个组 `step/2`） | 绝对 |
| 实测/推算 RMS | 0.165%（§7 复跑，格式性质） | 0.535%〔`kernels/sweep.json`〕 | 10.24%〔`bench/foldnoise.json`〕 |
| 小权重（`0.01σ`）的误差 | `0.165% × 0.01σ` | 仍是 `0.535% × σ`（比信号大 50 倍） | 更大 |
| 大权重（`4σ`）的误差 | `0.165% × 4σ` | 仍是 `0.535% × σ`（相对只有 0.13%） | 更大 |
| 动态范围 | `1e-38 … 3e38` | `±127s`，约 2 个数量级 | `±7s` |
| 丢 Adam 一步的条件 | 只对 `\|w\| > 2.6e-2` 丢 | 对所有元素**同时**丢，只要 `η < step/2` | 同左，门槛高 17 倍 |

第一行那个 0.165% 值得解释：bf16 的往返误差是格式自己的性质，把一百万个 `N(0, σ_W)` 样本过一遍 bf16 再回来，相对 RMS 就是 0.165%（§7 脚本，10 行）。理论上 `u/sqrt(12) = 0.11%` 是下界，0.2% 左右是上界，实测 0.165% 落在中间。

### 4.2 为什么 int8 反而"够用"

看 §4.1 的表会得出一个反直觉结论：**光看 RMS 误差，bf16（0.165%）比 int8 组 32（0.535%）更准 3.2 倍**。那为什么本项目的主权重必须是 int8？

答案是**容量**，不是精度：

```text
32.21 B 参数 × 2 B  = 64.42 GB     bf16，装不进 60 GB 内存
32.21 B 参数 × 1.0625 B = 34.22 GB  int8 组 32，装得下（§5）
```

而 int8 那 0.535% 的误差**不需要被前向看到**：本项目的前向用的是

```text
W_eff = deq(Ŵ) + P R          （见 00-notation §0.2）
```

`P R` 是 bf16 的精确残差累加器。折叠时 `Ŵ` 承担 0.535% 的噪声，`P R` 把"刚发生但还没写进 int8 的更新"精确保留。`runs/B/REPORT.md` §6 记录的端到端代价是：初始化时 `+0.28 nats`，训练 60 步后 `+0.04 nats`，120 步后 `+0.0007 nats`——**这三个数待重测**：它们是 1-block 的 loss 差值，而 1-block 跑在 2026-11-19 之前的错缩放 RMSNorm 上（`06` §0 的框）。机制（残差项吸收量化噪声）不受影响。也就是说 int8 存储的精度损失被残差项吸收掉了，而 bf16 省下的那 0.37 个百分点从来没有机会兑现成容量。

一句话：**int8 是唯一能装下的格式，而它的误差恰好是这套架构能吸收的那一种。**

## 5. 算一笔账：32.21 B 参数存五种格式

模型里有 32.21 B 个专家参数（40 层 × 256 专家 × (`gate_up` 1024×2048 + `down` 2048×512)，即每层 536.9 M + 268.4 M）〔`DESIGN.md` §2；`STATE.md` §2〕。逐格式：

| 存法 | 字节/参数 | 32.21 B 参数占用 | 出处 / 说明 |
|---|---|---|---|
| bf16 | 2.0000 | **64.42 GB** | 装不进 60 GB |
| int8 + 每输出通道 fp32 scale | 1.0039 | **32.34 GB** | 〔`research/sparse/accuracy.md` §5: 32.34〕 |
| int8 + 组 32 fp16 scale | 1.0625 | **34.22 GB** | 〔`DESIGN.md` §3.1: 34.2；`STATE.md` §1 的同一个 34.2〕 |
| int4 + 组 32 fp16 scale | 0.5625 | **18.12 GB** | 精度不可用（§6） |
| 2:4 稀疏 int8 + 组 32 + 2 bit 元数据 | 0.6250 | **20.13 GB** | 〔`research/sparse/accuracy.md` §5: 20.13〕，精度不可用 |

字节数怎么来的（以 `[m, n]` 矩阵、每输出通道一个 fp32 scale 为例）：

```text
scale 字节/参数 = m·4 B / (m·n) = 4/n
gate_up (n=2048): 1 + 4/2048 = 1.0020;  down (n=512): 1 + 4/512 = 1.0078
按参数量加权 (2:1): 1.0039  ->  32.34 GB
```

组 32 的 fp16 scale 则是 `2/32 = 0.0625` B/参数，与 `n` 无关——这就是为什么 `n` 小的矩阵（`down` 只有 512）用组量化反而更省。2:4 那一行是 `值 0.5 + scale 0.0625 + 元数据 2 bit/4 元素 = 0.0625`。

**这张表的结论**：只有 int8 的两行能进 60 GB，而组 32 比每通道只贵 1.9 GB（34.22 vs 32.34）。这在精度上是划算的（0.535% vs 0.828%，见 `02-quantization.md` §2），但在速度上不划算（组 32 的 int8 内核慢 2.4 倍，见 `03-tensor-cores.md` §2）——这是本项目里"精度 vs 速度"最锋利的一处取舍。

## 6. int4 为什么在这里死刑

### 6.1 实测：静态就已经崩了

在真实权重上做"存成 int4 再读回来"，什么都不训练：

| 格式 | 静态（不训练） | 20 次折叠后（lr=1e-4，每 50 步折一次） |
|---|---|---|
| int8 组 32，RTN | **0.565%** | **2.53%** |
| int4 组 32，RTN | **10.24%** | **12.33%** |
| int4 组 32，SR | — | **28.66%** |

第一列〔`bench/foldnoise.json`: `static_int8_g32` = 0.005651、`static_int4_g32` = 0.10243〕；第二列〔同文件 `int8_g32_lr0.0001_k50_sr0` 的 `func_rel` = 0.02532、`int4_..._sr0` = 0.1233、`int4_..._sr1` = 0.2866〕。

**int4 连"不训练"这一关都过不了**：10.24% 是权重相对误差，而 int8 是 0.565%，差 18 倍——正好是 `255/15 = 17`（§3.2 的台阶比）。

### 6.2 论证：台阶是 17 倍，单步更新是 0.052 个台阶

```text
int8 台阶 = 2 · 2.36σ / 255 = 1.14e-4
int4 台阶 = 2 · 2.36σ / 15  = 1.93e-3      （17 倍）
Adam 单步 ≈ η = 1e-4                        （04 篇 §3）
int4: η / step = 0.052
```

要让 int4 的折叠损失降到 5% 以下，每次折叠前累积的更新必须 ≥ 6.7 个台阶：

```text
6.7 × 1.93e-3 = 1.3e-2
按 |ΔW| ≈ η = 1e-4 线性累积，需要 130 步以上
（若按随机游走 √N·η 累积，需要 N ≈ (1.3e-2/1e-4)² ≈ 1.7e4 步）
```

〔`DESIGN.md` §5.1 用的是 1.5e-2 / 150 步的线性口径，同量级。〕而本项目的折叠间隔上限由 rank 决定：rank-32 承载不了上百步的累积更新（`DESIGN.md` §5.3、`05-galore-math.md`）。所以 **int4 不是"再调调参"的问题，是没有可行区间**。作为对照，int8 的 `η/step = 0.88`——单步更新也只有 0.88 个台阶，直接存进 int8 同样会被抹掉，这正是必须有残差累加器（`P R`）的原因。

### 6.3 而且换不到速度

`DESIGN.md` §5.1：16384 tokens/step 时 PCIe 2.75 s 与计算 2.76 s 打平，int4 把权重流量砍半只让 PCIe 变成 1.37 s，步时仍由计算决定，**tok/s 一点不涨**。省 16 GB 内存却买不到任何吞吐，还要付 12.33% 的误差——纯亏。

## 7. 复现脚本

```python
"""01 篇的算术复现。只需 numpy：python3 s01.py"""
import struct
import numpy as np

def u32(x):
    return struct.unpack("<I", struct.pack("<f", np.float32(x)))[0]

print("== 1. 位布局 ==")
u = u32(1.5)
print(f"  fp32 1.5 = {u:032b}  (sign 1 | exp 8 | mantissa 23)")
print(f"  bf16     = {(u + 0x8000) >> 16:016b}  (取高 16 位 -> sign 1 | exp 8 | mantissa 7)")
print(f"  fp16: 1|5|10   fp8-e4m3: 1|4|3   int8: 8 位补码，无指数无尾数")

print("\n== 2. bf16 的精度 ==")
one = u32(1.0)
nxt = struct.unpack("<f", struct.pack("<I", (one & 0xFFFF0000) + 0x00010000))[0]
print(f"  1.0 的下一个 bf16 = {nxt}  间距 2^-7 = {2**-7}")
print(f"  u = 间距/2 = 2^-8 = {2**-8:.6g} -> 小于 {2**-8*100:.3f}% 的相对增量会被丢掉")

w = 6.14e-3                                  # sigma_W（bench/foldnoise.json）
e = int(np.floor(np.log2(w)))
print(f"  w = {w:.3e} 落在 [2^{e}, 2^{e+1})，bf16 间距 = {2.0**(e-7):.3e}"
      f" = w 的 {2.0**(e-7)/w*100:.3f}%")

print("\n== 3. 定点台阶 ==")
s_meas, q_meas = 6.14e-3, 0.005346           # 实测 rel RMS（kernels/sweep.json）
amax = q_meas * s_meas * np.sqrt(12) * 255 / 2
print(f"  由实测 0.535% 反推组内 absmax = {amax:.3e} = {amax/s_meas:.2f} sigma")
for b in (8, 4):
    step = 2 * amax / (2**b - 1)
    print(f"  int{b}: step {step:.3e}  RMS {step/np.sqrt(12):.3e}"
          f" = {step/np.sqrt(12)/s_meas*100:.2f}% of sigma")
print(f"  台阶比 255/15 = {255/15:.1f}x")

print("\n== 4. bf16 往返误差（格式性质）==")
g = np.random.default_rng(0).normal(0, 6.14e-3, 1 << 20).astype(np.float32)
b16 = (((g.view(np.uint32) + 0x8000) >> 16).astype(np.uint32) << 16).view(np.float32)
print(f"  1M 个 N(0, sigma_W) 往返: rel RMS = "
      f"{np.sqrt(((b16-g)**2).mean())/np.sqrt((g**2).mean())*100:.3f}%")

print("\n== 5. 每步更新 vs 台阶 ==")
eta = 1e-4
for b in (8, 4):
    step = 2 * amax / (2**b - 1)
    print(f"  int{b}: eta/step = {eta/step:.3f}")
```

## 本篇要点

1. 浮点 = 符号 + 指数 + 尾数。指数买范围，尾数买精度，总位数固定时二者互斥；bf16 和 fp32 共享 8 位指数，所以范围一样、精度差 2^16 倍。
2. bf16 的半台阶 `u = 2^-8 = 3.9e-3`：任何小于某个数 0.39% 的增量会被**整个丢掉**，不是"有误差地加上去"。对 `σ_W = 6.14e-3`，那个阈值是 `3.05e-5`（0.497%）。
3. int8 / int4 是定点：`s = absmax/q_max`，`step = 2·absmax/q_max`，均匀分布下 `RMS = step/sqrt(12)`。高斯 + 组 32 时 `absmax ≈ 2.36σ`，于是 int8 的 `step ≈ 0.0185σ`、RMS 0.535% —— 与实测 `0.535%` 完全一致。
4. 同样的算术给 int4 预测 9.1%，实测静态 10.24%、折叠 20 次后 12.33%（`bench/foldnoise.json`）。台阶比 `255/15 = 17`，误差比 18，对得上。
5. bf16 往返是 0.165%（比 int8 组 32 的 0.535% 准 3.2 倍），但 bf16 主权重 64.42 GB 装不进 60 GB，int8 组 32 是 34.22 GB 装得下。**int8 是容量决策，不是精度决策。**
6. int8 的 0.535% 之所以无害，是因为前向用 `W_eff = deq(Ŵ) + P R`，残差项把误差吸收掉；实测端到端代价从 `+0.28 nats` 衰减到 `+0.0007 nats`（`runs/B/REPORT.md` §6）。
7. `η = 1e-4` 对 int8 只有 0.88 个台阶、对 int4 只有 0.052 个台阶。int4 要可用需累积 >6.7 个台阶（1.3e-2），线性口径要 130+ 步，rank-32 承载不了 → int4 无可行区间。
8. 位布局/台阶这些数是格式算术，`§7` 的脚本 30 行可当场复跑；但**具体到本项目的 0.535% / 10.24% / 12.33% 三个数只有 `bench/foldnoise.json` 与 `kernels/sweep.json` 里的落盘值算数**，不要用估算替代。
