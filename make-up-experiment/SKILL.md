# make-up-experiment（手工数值实验）

一句话：**编一套小到能心算、又自洽到能对拍的数据，把公式的每一步打印出来。**

读者读完应该能回答三个问题：这个量从哪来、这一步怎么算、这个数字为什么是它。

## 0. 什么时候用

- 用户说"我看不懂这个 loss / 更新 / 搜索到底在干什么"，想要**例子**而不是推导；
- 要把一篇论文/一份实现讲清楚，但真实系统要 7B 模型 + GPU + Lean；
- 要审计实现与论文是否一致（这时最后加一章"审计"，把差异写成可证伪断言）；
- 需要一个**长期可复跑**的教学材料（半年后还能 `python3 run_all.py` 出同一组数）。

不该用的时候：用户要的是"证明"，不是"算例"；或者对象本身没有可数的量（纯结构定理）。

## 1. 四条铁律

1. **单一数据源**：所有编造的量（状态、词表、logits、树、权重）放在一个 `data/*.json` 里。正文数字与脚本打印同源，改数据必须重跑。
2. **零依赖**：只用标准库（`math`/`json`），不装 torch、不连网、不碰 GPU。整套 10 个脚本应在 5 秒内跑完。
3. **每个数字都要能追**：正文里的数一律从脚本输出粘贴，不手抄；脚本末尾打 `PASS/FAIL`。
4. **玩具可以小，但公式不能变**：缩小维度（64→4、3584→2、4096→10），**不缩**符号约定、归一化分母、clamp 顺序、聚合顺序。

## 2. 目录骨架

```text
<主题>-数值实验/
  README.md                 入口：一句话 + 怎么跑 + 文件表
  00-导览与记号.md           路线图、记号表、玩具世界、依赖
  01-….md … NN-….md         每章一个概念，可单独读
  cheatsheet.md             公式卡 + 误解表 + 问题索引
  code/
    toy.py                  共享零依赖库（softmax/CE/树递归/优化器/断言器）
    c01_*.py … cNN_*.py     每章一个脚本，打印正文里的表
    run_all.py              --upto N，汇总 PASS/FAIL
  data/
    toy_world.json          唯一数据源
```

## 3. 每章六段模板

固定结构，让读者形成肌肉记忆：

1. **速查**（3 行 + 指回既有笔记的章节号）
2. **这是什么 / 为什么需要**（不超过两段，先说"没有它会怎样"）
3. **定义**（公式放 `text` 围栏，小公式不写 LaTeX）
4. **手算**（3–6 个数，一张 4–6 列的表；表后必须有一段"读法"）
5. **代码复现**（一行命令 + 关键断言的输出片段）
6. **三条常见误解 + 仓库对照**（`file:line`，让读者能对上真实代码）

模板见 [templates/chapter.md](templates/chapter.md)。

## 4. 玩具尺度：缩什么、不缩什么

| 真实 | 玩具 | 理由 |
|---|---|---|
| 64 桶价值头 | 4 桶 | 手算 softmax 只要 4 个数 |
| hidden 3584 | 2 | 权重表能印在纸上 |
| batch 4096 | 10 | 能列全表，还能掺 1 条 SFT |
| 1e6 步 | 3 步 | 看趋势不需要收敛 |
| 7B 参数 | 8 个 | 一次更新能逐坐标算 |
| 12 万词表 | 12 个 token | 覆盖所有候选动作即可 |

**不缩的**：符号方向（`V = -d`）、分母（`1/n_a`、`N_v`）、clamp 的位置与顺序、AND/OR 的 `min`、`ignore_index`、权重归一化、优化器的 β/ε/wd。

判断标准：**把真实实现里的这一行代码抄下来，玩具里必须还是同一行，只是张量变小。**

## 5. 数据源与代码的分工

`data/toy_world.json` 只放"世界"：词表、状态文本、树形、logits 行、候选动作、参数初值。

`code/toy.py` 只放"数学"：softmax、log_softmax、CE、KL、two-hot、树递归、AdamW、`Checker`、`table`。

章节脚本只放"这一章的账"：读数据 → 调库 → 打表 → 断言。

反例：把 `two_hot` 复制进每个脚本（改一次要改十处）。

## 6. 两个范例

### 6.1 搜索侧：MCTS 逐轮手算

`MCTS算法流程/V1-MCTS完整运行流程与算例.md`（历史）与 `MCTS算法流程/V2-MCTS当前实现完整运行流程与算例.md`（现行），同目录下。

它示范的是**时间轴型**实验：一轮一张表。

```text
迭代 1  根展开，GPU 调用 #1，value=4 ⇒ V=-4，4 个候选先验 0.4444/0.3333/0.1111/0.1111
迭代 2  c(1)=0.0016248，FPU Q=γ^35=0.703448，选出 a1（score 0.704260）
迭代 3  a1 已访问：v=(-3)-1=-4，Q=γ^3=0.970299；改攻 f1（AND 的另一个子目标）
```

风格要点：

- 每轮固定四件事：`c(N)`、每个孩子的 `Q`/`U`/`score`、选谁、回传后的 `valueSum/numVisit`；
- 数字精确到 6 位，且**能被下一轮引用**（迭代 3 用的 `-3` 来自迭代 2）；
- 发现反直觉的事实时加"注记"：τ=200 让三个先验只差 6e-4，排序接近"谁先生成谁先展开"。

### 6.2 训练侧：CE 更新的十章

`~/文档/mcts-theory-learning/CE-专家迭代/`（README + 00–10 + cheatsheet + `code/` + `data/`）。

它示范的是**依赖链型**实验：每一章的输出是下一章的输入。

```text
01 logits → p        p(constructor)=0.4000, log p=-0.916288
02 CE = KL + H(q)    0.914369 = 0.016423 + 0.897946
03 逐 token CE       0.916288 / 0.433804 / 0.410537
04 two-hot + α≡0     d=2.5 ⇒ (0.5, 0.5)，H(q)=ln2；整数 d ⇒ α=0
05 value_target      OR -1+子，AND min ⇒ d=2/1/1
06 64 桶头           d̂=2.023268，∂CE/∂z=p−q
07 λ_eff             λ=1e-3 × 10/9 = 1.111e-3
08 AdamW             梯度×10 轨迹差 2.7e-9；ε 在 g~1e-9 时接管
09 端到端            L=0.588125，一步后 L_val −3.07e-4
10 审计              5 条可证伪断言（α≡0、差常数 N、λ_eff、τ 错位、终端退化）
```

风格要点：

- 每章开头 3 行"速查"指回已有笔记，**不重复推导**；
- 每章末尾"三条误解"，必须是真踩过的（如"CE 是距离"、"value_loss 应降到 0"）；
- 最后单独一章做**审计**：把"与论文的差异"写成可证伪断言 + 判决表 + 修改建议，而不是散文式比较。

## 7. 工作流（建议按此顺序）

1. **圈一条链**：从输入到输出的最小闭环（如 `logits → CE → 一步更新`），别贪多。
2. **定玩具世界**：词表/状态/树/参数，写进 JSON；先确认"够用且自洽"（概率和为 1、树能递归到底）。
3. **写 `toy.py`**：只放这一条链需要的算子。
4. **写第一张表**：从最靠近输入的那一步开始（softmax），跑出数。
5. **写正文**：把跑出来的数粘进表，加"读法"段。
6. **加断言**：每章 3–6 条，必须是"如果实现错了就会 FAIL"的断言。
7. **重复 4–6**，每章只依赖前面已出现的量。
8. **收尾**：`00`（路线图）+ `README` + `cheatsheet` + `run_all.py`。
9. **验收**：见 §9。

## 8. 反模式

| 反模式 | 后果 |
|---|---|
| 用"看起来合理"的数但没算过 | 第三章就对不上，全文返工 |
| 手抄数字进 md | 改一次数据，十处失真 |
| 直接拿真模型/真 API 当前向 | 不可复现、数字不可读、读者无法核对 |
| 玩具失真（把 64 桶说成"步数/64"） | 教错了语义，比不教更糟 |
| 只给推导不给数字 | 读者仍然不知道"这一步算出多少" |
| 每章自造一套数据 | 依赖链断裂，无法端到端 |
| 用 LaTeX 写小公式 | 渲染风险 + 读者没法复制去算（见 `md-latex-rule`） |
| 不声明"哪些是玩具" | 读者把玩具结论当真实结论 |
